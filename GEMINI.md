# Gemini — ASTRA entry point

This repository is an independent Babylon.js prototype. The owner authorized development, reuse with provenance, the separate delivery-candidate repository and updates to both Sites. It is not an official NASA submission; do not infer eligibility or organizer approval.

## Start from the current state

1. Read `AGENTS.md`, `README.md`, `HANDOFF.md`, `MASTER_GOAL.md`, `TEST_REPORT.md` and `ACCEPTANCE.json`; inspect `git status`, source and tests before editing. Older planning documents contain proposals, not current acceptance.
2. The source includes five finite regions, 13 GLBs (eight legacy and five skinned characters), optional Cometa, Scout, ten episode beats and local SVG portraits. Cargo, loadout, auxiliary ports and a bounded field kit are implemented. Preserve the pure simulation as resource authority; its state is version 3 and save envelope version 4.
3. Use Node 24, `npm ci`, `npm run check` and `npm run test:e2e` as applicable. The browser script executes a real CDP workflow; check `docs/demo/E2E_REPORT.json` and `TEST_REPORT.md` for conditions, failures and results. CPU/NullEngine and software rendering do not establish hardware-GPU or human acceptance.
4. Consult `docs/PUBLICATIONS.json` for the final state of both authorized Sites and their source revisions. Do not automatically submit to an event or invite collaborators. Preserve actual history, asset rights and AI disclosure.

## Skills by task

Read the relevant `.agents/skills/*/SKILL.md` explicitly; do not load all 13 indiscriminately. Use `astra-batch-delivery` for planning; `astra-science-gameplay` for simulation; `astra-babylon-review` for world work; and applicable animation, input, camera, UI, save or performance skills for those tasks. Upstream examples are conceptual references, not instructions to change engine. See `docs/skills/README.md` and `docs/skills/DESIGN_APPLICATION.md` for provenance.

The eight labelled `docs/art/` boards are design references, not gameplay captures. Review the current source and actual browser evidence before changing characters or episode scenes. Keep fictional science, test limitations and unresolved competition rules explicit. Continue reversible work without reopening decisions already authorized by the owner.
