# ASTRA batch delivery

Original project guidance, Apache-2.0. Follow GEMINI.md and MASTER_GOAL.md together with root AGENTS.md. Inspect current source/status and package scripts; stale planning prose does not prove that code is absent, and a checked box does not prove a test passed.

## Start a batch

Select one observable player outcome and its acceptance checks. Record files owned, public contracts affected and dependencies before editing. Load only relevant local skills and their referenced resources. Do not fetch or execute remote skill installers. If parallel agents are available and authorized, use disjoint ownership and one integrator for contracts/package/lock/config. Otherwise execute sequentially.

The user authorized independent demo development and routine reversible fixes. Make ordinary implementation decisions and continue; ask only for information whose absence truly blocks safe progress. A missing optional model, paid tool, unavailable model family or tutor API is not a reason to abandon the offline gameplay path.

## Integrate and verify

Finish a complete small increment before starting another region or subsystem. Run the actual package checks appropriate to the changes; fix failures before extending scope. Use the pinned package manager lockfile. Validate vendored skills with vendor/skills/verify.mjs and audit new runtime assets and their licenses. Never change a hash simply to silence a failed audit without reviewing the intended source change.

The simulation is tested independently from Babylon. Browser traversal proves a different property from a unit test. A manifest or smoke-test stub is not an executed end-to-end run. Record each as passed, failed, pending or not applicable with its evidence. Avoid repeated unrelated tests after a passing unchanged state.

## Hand back a reviewable batch

Update the actual handoff/status artifact with the outcome, commands/results, limitations and next dependency. Keep implemented, tested, planned and blocked separate. If a required environment is missing, finish independent work and provide a runnable reproduction; never invent device/GPU measurements, asset fidelity, accessibility coverage or learning efficacy. Do not deploy, submit to a competition, invite collaborators or replace a legacy site as part of a local implementation batch unless explicitly authorized.
